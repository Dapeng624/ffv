# 映作核心功能复刻范围

> 版本：V0.2
> 目标：对齐 Higgsfield 类产品的核心生成能力与工作流，不复制品牌、素材或源代码。

## 1. “1:1 复刻”的工程定义

本项目所说的 1:1，指用户能力、操作路径、任务状态和结果管理尽量等价，不代表复制对方商标、文案、演示视频、受保护视觉资产或前端代码。

优先级顺序：

1. 生成能力和参数完整性。
2. 素材、任务与结果的可靠性。
3. 模型可替换性与成本控制。
4. 相似的信息架构和操作效率。
5. UI 细节、登录和支付系统。

## 3. 当前核心闭环

```text
选择生成模式
-> 上传所需素材
-> 素材写入 R2
-> 元数据写入 D1
-> 设置 Prompt、比例、时长、镜头和运动强度
-> 服务端校验素材归属与类型
-> 模型适配器创建供应商任务
-> 本地任务进入 queued
-> 前端轮询 processing / progress
-> 成功后保存 output_url
-> 历史任务恢复和结果播放
```

当前没有登录系统，通过服务端签发的匿名工作区 Cookie 隔离素材和任务。接入正式登录后，将 `guest_id` 迁移或映射到 `user_id`，核心数据结构无需重写。

## 4. 正式模型接入接口

每个视频模型供应商需要实现统一适配器：

- `submit(input)`：提交生成请求，返回供应商任务 ID 和实际模型 ID。
- `getStatus(providerTaskId)`：查询状态、进度、结果和错误。
- 后续补充 `cancel(providerTaskId)`：供应商允许时取消。
- 后续补充 `normalizeError(error)`：统一限流、审核、余额和模型错误。

业务层只认识统一任务状态，不直接依赖供应商字段。

当前 Seedance 适配器使用火山方舟 `POST /contents/generations/tasks` 创建任务，并通过 `GET /contents/generations/tasks/{id}` 同步状态。上传到 R2 的参考素材通过 30 分钟 HMAC 签名 URL 提供给模型，普通访客仍需匿名工作区 Cookie 才能读取素材。

### 本地环境变量

从 `.env.local.example` 创建 `.env.local`，至少配置：

```dotenv
VIDEO_PROVIDER=seedance
ARK_API_KEY=你的火山方舟APIKey
ARK_VIDEO_MODEL=控制台中的模型ID或EndpointID
PUBLIC_APP_URL=https://模型可访问的公网地址
ASSET_SIGNING_SECRET=独立的长随机字符串
```

`PUBLIC_APP_URL` 不能是 `localhost`，因为火山方舟需要从公网拉取参考素材。只测试文生视频时不需要素材 URL，但建议正式环境始终配置。

## 5. 下一阶段顺序

### Phase A：正式视频 API

- 已选定首个供应商：火山方舟 Seedance。
- 已实现真实提交和轮询。
- 将生成结果转存 R2。
- 增加超时、重试、回调验签和错误映射。
- 记录每次请求实际成本。

### Phase B：参考控制能力

- First/Last Frame 模型参数映射。
- Motion Control 参考视频映射。
- 视频编辑与局部修改。
- 角色、商品和场景参考资产复用。
- 多结果并排比较与再次生成。

### Phase C：Cinema Studio

- Hero Frame First 工作流。
- 机身、镜头、焦段和景深控制。
- 最多三个镜头运动叠加。
- 色彩时代、类型和节奏预设。
- 分镜、参考资产和项目管理。

## 6. 暂不进入核心层

- 正式 UI 模板替换
- 用户注册与第三方登录
- 套餐、积分余额与支付
- 营销落地页
- 团队和邀请

这些模块后续通过独立模板接入，不能反向污染模型任务与素材存储层。
